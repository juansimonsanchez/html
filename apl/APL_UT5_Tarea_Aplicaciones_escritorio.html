1. DESCRIPCIÓN GENERAL. OBJETIVOS ¶

El alumno, actuando como Administrador de Sistemas de una PYME, montará un servidor unificado que ofrezca servicios de escritorio web a la plantilla de trabajadores. Para ello, partiendo de una máquina virtual limpia con Ubuntu/Debian Server, deberá desplegar la suite LAMP, configurar el cliente de Webmail Roundcube enlazado a un servidor de correo e implementar un gestor de calendario Baïkal basado en CalDAV.

Objetivos de Competencia Técnica:

  1. Instalar y securizar el stack de servicios LAMP (Apache, MariaDB, PHP) en Linux.

  2. Desplegar bases de datos relacionales asociadas a aplicaciones de infraestructura.

  3. Enlazar protocolos cliente-servidor seguros mediante la alteración de scripts PHP de configuración.

  4. Validar el entorno de trabajo mediante pruebas directas de inicio de sesión y creación de citas.

2. CONSIDERACIONES PREVIAS ¶

  • Disponer de una Máquina Virtual en el aula de informática con Ubuntu Server o Debian Server configurada con direccionamiento IP Estático (Modo Puente o Red Interna).

  • Conectividad de red operativa para la descarga de paquetes.

  • Identificador del servidor de correo de pruebas del aula: IP_SERVIDOR_CORREO provisto por el docente, configurado con protocolos IMAP (Puerto 143) y SMTP (Puerto 25).

3. EXPLICACIÓN DETALLADA (PASO A PASO) ¶

Fase 1: Preparación de la Infraestructura LAMP y Base de Datos Relacional ¶

El alumno deberá conectarse a su servidor mediante terminal y ejecutar la instalación de Apache, MariaDB y PHP con los módulos requeridos para el procesamiento de correo y XML.

Posteriormente, accederá a la consola de MariaDB para crear de forma segura la estructura relacional:

# 1. Instalación del entorno base y sus dependencias
sudo apt update && sudo apt install -y apache2 mariadb-server
php php-mysql php-imap php-mbstring php-xml wget unzip
# 2. Creación del entorno de aislamiento de datos para la aplicación
de escritorio web
sudo mysql -e "CREATE DATABASE roundcube_db CHARACTER SET utf8
COLLATE utf8_general_ci;"
sudo mysql -e "CREATE USER 'roundcube_user'@'localhost' IDENTIFIED BY
'PasswordCorporativa2026_!';"
sudo mysql -e "GRANT ALL PRIVILEGES ON roundcube_db.* TO
'roundcube_user'@'localhost';"
sudo mysql -e "FLUSH PRIVILEGES;"

Realizar una captura del terminal donde se evidencie la ejecución correcta de las sentencias SQL de base de datos.

Fase 2: Despliegue y Enlace Estructural del Cliente Webmail Roundcube ¶

El alumno descargará el paquete completo de Roundcube Webmail, lo extraerá en la ruta raíz del servidor web Apache y volcará el esquema estructurado de tablas inicial sobre la base de datos de producción:

cd /tmp
wget
https://github.com/roundcube/roundcubemail/releases/download/1.6.6/roundcubemail-1.6.6-complete.tar.gz
tar -xzvf roundcubemail-1.6.6-complete.tar.gz
sudo mv roundcubemail-1.6.6 /var/www/html/webmail
# Importación del esquema SQL estructurado
sudo mysql roundcube_db <
/var/www/html/webmail/SQL/mysql.initial.sql
# Aplicación de permisos restrictivos asignados al usuario del
servidor web (www-data)
sudo chown -R www-data:www-data /var/www/html/webmail/temp
/var/www/html/webmail/logs
sudo chmod -R 750 /var/www/html/webmail/temp
/var/www/html/webmail/logs

A continuación, el alumno configurará el archivo de enlace de la aplicación copiando la plantilla base en /var/www/html/webmail/config/config.inc.php y alterando sus variables internas para establecer la conexión con la base de datos y definir de forma explícita los sockets de comunicación de correo IMAP/SMTP:

<?php
$config['db_dsnw'] =
'mysql://roundcube_user:PasswordCorporativa2026_!@localhost/roundcube_db';
$config['imap_host'] = 'ssl://IP_SERVIDOR_CORREO:993'; // Reemplazar
por la IP del aula
$config['smtp_host'] = 'tls://IP_SERVIDOR_CORREO:587'; // Reemplazar
por la IP del aula
$config['smtp_user'] = '%u';
$config['smtp_pass'] = '%p';
$config['product_name'] = 'Portal Webmail - Empresa SMR';
$config['skin'] = 'elastic';
?>

Adjuntar captura del contenido editado del archivo config.inc.php prestando atención a los parámetros de red.

Fase 3: Verificación de Acceso y Validación de Servicios de Correo ¶

El alumno abrirá el navegador web en una máquina cliente apuntando a la dirección http://<IP_DE_TU_SERVIDOR>/webmail. Introducirá las credenciales del buzón de pruebas corporativo asignado a su puesto de taller.

Tras verificar el inicio de sesión exitoso, redactará un correo saliente dirigido al buzón del profesor para validar el enrutamiento SMTP, comentando la captura de pantalla del registro log del servidor si fuese necesario para demostrar el éxito de la operación.

¶

Fase 4: Despliegue de Servicios de Productividad y Calendarios Web con Baïkal ¶

Para la gestión del tiempo y agendas de la organización, el alumno instalará el servidor ligero Baïkal en el directorio raíz web:

cd /var/www/html
sudo wget
https://github.com/sabre-io/Baikal/releases/download/0.9.5/baikal-0.9.5.zip
sudo unzip baikal-0.9.5.zip
sudo mv baikal calendario
sudo chown -R www-data:www-data /var/www/html/calendario
sudo chmod -R 755 /var/www/html/calendario/Specific
El alumno accederá a http://<IP_DE_TU_SERVIDOR>/calendario/html/ desde el navegador cliente para completar el asistente técnico. Tras definir el usuario administrador del portal de agendas, accederá al panel de control para dar de alta una cuenta de usuario corporativa y crear un calendario compartido bajo el nombre Mantenimientos_SMR. Conectará un cliente de escritorio externo compatible o utilizará la interfaz para insertar una cita programada.

¶

Fase 5: Fortalecimiento de la Aplicación y Cierre de Seguridad (Hardening) ¶

Como fase final obligatoria para garantizar un entorno de producción seguro, el alumno endurecerá el sistema eliminando los scripts del asistente web y bloqueando accesos no autorizados a los archivos de configuración:

# Eliminación irreversible de la interfaz del instalador web
sudo rm -rf /var/www/html/webmail/installer
# Restricción de permisos sobre el archivo de credenciales de
configuración de base de datos
sudo chmod 640 /var/www/html/webmail/config/config.inc.php

Captura del terminal donde se verifique mediante un comando ls -l que la carpeta installer ha desaparecido y que los permisos del archivo config son restrictivos.

CRITERIOS DE CALIFICACIÓN (RÚBRICA GENERAL) ¶

Indicador Excelente (5 pts) Aceptable (3 pts) Insuficiente (1-0 pts)

El servidor Baïkal gestiona citas correctamente. Las aplicaciones se encuentran operativas, pero presentan fallos leves en su integración (ej: permite la lectura del buzón pero fallan los envíos salientes SMTP). Error persistente en la conexión con las bases de datos o fallos de infraestructura 500/404 que impiden cargar los portales web de escritorio.
Memoria y Documentación (40%) Documento PDF impecable, con justificación de márgenes. Explica con rigor la función de cada comando de consola y los parámetros aplicados en los scripts PHP. Memoria descriptiva completa pero superficial. Muestra los pasos realizados pero carece de un análisis teórico sobre la utilidad de las configuraciones aplicadas. Entrega incompleta, desorganizada, sin justificar o consistente en una sucesión de capturas de pantalla desprovistas de explicaciones textuales.
Presentación y Código (10%) Archivos de configuración modificados entregados en la estructura .zip limpia, perfectamente tabulados y con comentarios explicativos insertados por el alumno. No se aportan los archivos de código fuente configurados o la tarea se entrega fuera del plazo establecido en la plataforma.
