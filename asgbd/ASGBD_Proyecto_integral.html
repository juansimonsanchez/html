INTRODUCCIÓN GENERAL AL PROYECTO ¶

¡Bienvenido al equipo de ingeniería de AeroData Solutions S.L.! Acabas de ser contratado como Administrador de Sistemas y DBA Principal (Database Administrator). La compañía ofrece servicios críticos de consultoría aeronáutica, control de tráfico de pasajeros y análisis de trayectorias de vuelo a escala internacional utilizando un volumen masivo de datos.

Tu objetivo a lo largo del curso académico es construir la infraestructura de datos de la empresa desde cero, escalando el servidor desde un único nodo hasta una arquitectura distribuida y monitorizada mediante Inteligencia Artificial (IA), estructurada en 6 fases lógicas:

1. DESCRIPCIÓN GENERAL DE LA TAREA. OBJETIVOS ¶

El departamento de desarrollo necesita desplegar una instancia limpia y aislada de MySQL 8.0 en la infraestructura local. Debes automatizar el despliegue mediante Docker, parametrizar la memoria del motor de almacenamiento InnoDB para un uso eficiente de los recursos del host y activar de forma persistente los sistemas de logs y auditorías.

2. CONSIDERACIONES PREVIAS ¶

Asegúrate de contar con Docker y Docker Compose instalados en tu máquina virtual Ubuntu Server. El contenedor deberá mapear los volúmenes del motor para evitar pérdidas accidentales de datos si el servicio se reinicia.

3. EXPLICACIÓN DETALLADA (PASO A PASO) ¶

  1. Despliegue de Contenedores: Diseña un archivo docker-compose.yml que levante un servicio MySQL 8.x mapeando el puerto del host, configurando almacenamiento persistente para /var/lib/mysql y un montaje de tipo bind para un archivo custom.cnf.

  2. Hardening de Configuración (custom.cnf): Configura los parámetros bajo el bloque [mysqld] para asegurar el comportamiento del servidor:

    • Limita las conexiones simultáneas fijando un umbral razonable (max_connections).

    • Deshabilita la importación de archivos locales arbitrarios mediante la directiva local_infile = OFF.

    • Habilita el Log General de Consultas y el Log de Consultas Lentas (slow_query_log), estableciendo un umbral de detección de consultas lentas de segundos (long_query_time = 2.0).

  3. Persistencia Dinámica: Entra al terminal de la base de datos y demuestra cómo leer y modificar una variable global (ej: autocommit) en caliente usando persistencia de configuración del motor (SET PERSIST), documentando el impacto en el archivo de autoconfiguración persistente de MySQL (mysqld-auto.cnf).

4. PREGUNTAS TEÓRICAS Y DE INVESTIGACIÓN ¶

  1. ¿Cuál es el impacto en términos de rendimiento de E/S y almacenamiento físico si decidimos mantener activo el general_log = ON permanentemente en un entorno de Big Data en producción?

  2. Explica brevemente la diferencia práctica entre una variable con alcance GLOBAL, SESSION y PERSIST dentro del ciclo de vida del SGBD.

1. DESCRIPCIÓN GENERAL DE LA TAREA. OBJETIVOS ¶

AeroData Solutions requiere un sistema estricto de accesos lógicos para el cumplimiento de normativas de seguridad de datos. Implementarás un modelo de seguridad basado en roles (RBAC) y configurarás políticas globales de contraseñas de nivel empresarial en MySQL.

2. CONSIDERACIONES PREVIAS ¶

La base de datos del sistema mysql contiene los privilegios y accesos globales de la instancia. Todas las sentencias de creación de roles, asignación y herencia de privilegios deben realizarse con la cuenta administrativa con máximos privilegios (root).

3. EXPLICACIÓN DETALLADA (PASO A PASO) ¶

  1. Configuración de Políticas de Hardening de Claves: Modifica tu archivo custom.cnf para exigir que las contraseñas globales tengan un tiempo de caducidad máximo de 90 días, requieran un histórico que impida reutilizar las últimas 3 contraseñas y bloquee cuentas automáticamente tras 3 intentos fallidos de autenticación.

  2. Creación de Roles Corporativos: Implementa en código SQL puro los siguientes perfiles de acceso:

    • Rol aerodata_analyst: Acceso exclusivo de lectura (SELECT) sobre el esquema analítico global.

    • Rol aerodata_operator: Permiso para consultar,
insertar y actualizar reservas y tickets, pero con bloqueo estricto de
borrado (DELETE denegado).

    • Rol aerodata_admin: Administrador secundario del esquema de vuelos, con capacidad para gestionar usuarios y roles locales, pero restringido para alterar datos internos del motor.

  3. Mapeo de Usuarios: Crea un usuario para cada departamento asignado, configúrale sus credenciales, asígnale el rol correspondiente y activa la funcionalidad SET DEFAULT ROLE para que las credenciales hereden el alcance de permisos inmediatamente al iniciar sesión.

4. PREGUNTAS TEÓRICAS Y DE INVESTIGACIÓN ¶

  1. Investiga el principio de seguridad informática del "Menor Privilegio" (Least Privilege). ¿Cómo contribuye el uso de roles (RBAC) a la mitigación de ataques de inyección SQL o robo de credenciales en comparación con otorgar accesos individuales?

  2. Explica cómo maneja MySQL la herencia de permisos y de qué manera la vista mysql.role_edges documenta las dependencias del diccionario de datos.

1. DESCRIPCIÓN GENERAL DE LA TAREA. OBJETIVOS ¶

Los flujos de inserción de vuelos requieren reglas de validación en tiempo real para impedir anomalías en la programación espacial del aeropuerto. Además, el departamento de control necesita generar informes consolidados de pasajeros y automatizar el traspaso de datos históricos para liberar memoria activa de almacenamiento en disco.

2. CONSIDERACIONES PREVIAS ¶

Dado que utilizaremos la base de datos real airportdb, debes asegurar la consistencia transaccional de los datos históricos. Asegúrate de declarar correctamente los bloques transaccionales e incluir los manejadores de salida (DECLARE CONTINUE HANDLER) al procesar los cursores lógicos.

3. EXPLICACIÓN DETALLADA (PASO A PASO) ¶

  1. Trigger de Integridad Espacial (tr_validar_ruta_vuelo): Desarrolla un disparador BEFORE INSERT en la tabla de vuelos (flight) que verifique dos condiciones:

    • El aeropuerto de salida (from_airport) y el de llegada (to_airport) no pueden coincidir.

    • La fecha programada de salida (scheduled_departure) debe ser estrictamente posterior al instante actual (NOW()).

    • Si alguna condición falla, detén la operación mediante el lanzamiento de un error estructurado (SIGNAL SQLSTATE '45000').

  2. Función de Formateo Analítico (listado_pasajeros_vuelo): Crea una función que reciba el identificador de un vuelo y, mediante el uso de un Cursor, recorra los datos de los pasajeros asociados al mismo, devolviendo un único string concatenado con los nombres separados por un guion medio (-).

  3. Procedimiento Almacenado con Control de Errores y Transacciones (archivar_vuelos_antiguos): Desarrolla un procedimiento transaccional seguro que busque todos los registros de vuelos completados cuya fecha sea anterior a un parámetro temporal dado. El procedimiento debe:

    • Declarar un cursor para iterar de manera ordenada las filas afectadas.

    • Mover cada vuelo a una tabla histórica de auditoría (flight_history) y eliminarlo de la tabla operativa principal.

    • Garantizar el aislamiento utilizando bloques transaccionales seguros (START TRANSACTION, COMMIT y ROLLBACK en caso de excepciones imprevistas).

4. PREGUNTAS TEÓRICAS Y DE INVESTIGACIÓN ¶

  1. ¿Por qué se considera que las rutinas almacenadas (procedimientos y funciones) mejoran el rendimiento de la red corporativa al ejecutar consultas analíticas complejas en comparación con consultas SQL crudas enviadas de forma individual desde aplicaciones cliente remotas?

  2. Explica qué es un SQLSTATE y por qué es importante mapear los códigos de error estándar en aplicaciones críticas de administración de bases de datos.
