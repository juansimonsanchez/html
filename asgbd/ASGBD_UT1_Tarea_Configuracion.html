Bloque I: Implantación y Verificación del Motor (RA1)

Actividad 1: Investigación – Selección y Componentes del SGBD CE 1.a, 1.b, 1.c, 1.d

Responde de manera sintética y justificada a las siguientes cuestiones en tu memoria:

  1. Diferenciación técnica: Explica en 3 o 4 líneas la diferencia operativa entre el proceso demonio en segundo plano (mysqld) y las herramientas clientes de línea de comandos (mysql y mysqldump).
  2. Jerarquía modular de configuración: Inspecciona el fichero /etc/mysql/my.cnf. Describe cuál es el propósito de separar las directivas de inclusión mediante:
    • /etc/mysql/conf.d/
    • /etc/mysql/mysql.conf.d/
  3. Selección del gestor: Justifica por qué para una plataforma web corporativa con alta concurrencia transaccional se elige un motor cliente-servidor relacional como MySQL/MariaDB frente a un gestor monolítico embebido como SQLite.
  4. Software base y dependencias: Enumera 3 librerías o utilidades base del sistema operativo necesarias para instalar y compilar/desplegar el servicio de base de datos (ej. libaio1, paquetes de certificados CA o utilidades de resolución de red).
  5. Comparativa de motores de almacenamiento: Completa la siguiente tabla en tu informe:
Característica Técnica Motor InnoDB Motor MyISAM
Soporte de Transacciones (ACID)
Granularidad de Bloqueo (Fila vs. Tabla)
Integridad Referencial (Foreign Keys)

Actividad 2: Auditoría Previa de Requisitos Hardware CE 1.e

Comprueba si el equipo o máquina virtual de prácticas cumple con los requisitos mínimos de explotación antes de proceder con el despliegue del servicio:

# Comprobar núcleos y arquitectura de la CPU
lscpu | grep -E "Model name|CPU\(s\):|Architecture"

# Comprobar memoria RAM total y disponible
free -h

# Comprobar espacio libre en disco en la partición raíz
df -h /

Entrega una captura con los resultados obtenidos y argumenta si son suficientes para soportar una instancia de desarrollo (recomendado: 1-2 núcleos, 2 GB RAM y 10 GB de disco).

Actividad 3: Instalación y Documentación del Proceso CE 1.f, 1.g

Despliega el motor MySQL Server mediante el gestor de paquetes de tu distribución Linux:

sudo apt update && sudo apt install -y mysql-server # Ya se realizó
sudo systemctl status mysql --no-pager

Adjunta una captura de la consola donde se visualice el estado active (running) junto al prompt de tu terminal.

Actividad 4: Análisis de Ficheros de Registro y Diagnóstico CE 1.h

Examina los mensajes generados durante el arranque inicial del servidor inspeccionando el fichero de error:

sudo tail -n 25 /var/log/mysql/error.log
  1. Indica qué línea del registro certifica la versión exacta con la que ha levantado el motor.
  2. Localiza el mensaje que confirma que el socket UNIX está listo para recibir conexiones.
  3. Identifica si aparece algún aviso de severidad [Warning] y explica su significado técnico.

Actividad 5: Resolución de Incidencias en la Instalación CE 1.i

Simula y corrige un fallo típico de bloqueo de puerto de escucha:

  1. Detén el servicio (sudo systemctl stop mysql) y ocupa el puerto estándar: 
    sudo nc -l -p 3306 &
  2. Intenta arrancar MySQL (sudo systemctl start mysql), constata que entra en estado fallido e inspecciona el motivo con: 
    journalctl -xeu mysql.service --no-pager -n 20
  3. Finaliza el proceso en conflicto (sudo killall nc), levanta el servicio y redacta en la memoria la explicación técnica de la causa y la corrección.

Bloque II: Configuración Modular del Motor y Clientes (RA2)

Actividad 7: Control del Servicio e Inicio/Parada CE 2.a

  1. Comprueba si el demonio arrancará de forma persistente tras el encendido del sistema: 
    systemctl is-enabled mysql
  2. Reinicia el servicio y aporta una captura donde se evidencie la renovación del tiempo de actividad (uptime): 
    sudo systemctl restart mysql
systemctl status mysql --no-pager

Actividad 8: Estado Inicial de Logs y Variables de Entorno CE 2.e, 2.f, 2.g

Conéctate al gestor y comprueba las directivas asignadas por defecto en la memoria del motor:

SHOW GLOBAL VARIABLES LIKE 'general_log%';
SHOW GLOBAL VARIABLES LIKE 'log_bin%';
SELECT @@GLOBAL.autocommit, @@GLOBAL.default_password_lifetime, @@GLOBAL.max_connections, @@GLOBAL.wait_timeout;

Aporta captura comentando los valores por defecto devueltos.

Actividad 9: Configuración Física del Demonio en mysql.conf.d/ CE 2.b, 2.e, 2.f, 2.g

Crea el archivo modular /etc/mysql/mysql.conf.d/99-server-custom.cnf para aplicar directivas al demonio servidor:

[mysqld]
# Red y Conexiones (CE 2.e, CE 2.g)
bind-address              = 0.0.0.0
max_connections           = 80
wait_timeout              = 600

# Características por defecto y Motor (CE 2.b, CE 2.f)
default_storage_engine    = InnoDB
character-set-server      = utf8mb4
collation-server          = utf8mb4_unicode_ci
autocommit                = OFF
default_password_lifetime = 270

# Auditoría y Sistema de Logs
slow_query_log            = ON
slow_query_log_file       = /var/log/mysql/slow_querys.log
long_query_time           = 2.000000
  1. Reinicia el servicio: sudo systemctl restart mysql.
  2. Comprueba en la consola SQL que las variables se cargaron correctamente: 
    SHOW GLOBAL VARIABLES WHERE Variable_name IN (
    'bind_address', 'max_connections', 'wait_timeout',
    'default_storage_engine', 'character_set_server',
    'autocommit', 'default_password_lifetime', 'slow_query_log'
);

Aporta captura del fichero editado y de la comprobación SQL.

Actividad 10: Aseguramiento de Cuentas de Administración CE 2.c

  1. Comprueba el plugin de autenticación del usuario administrador: 
    SELECT user, host, plugin FROM mysql.user WHERE user = 'root';
  2. Establece una contraseña robusta para la cuenta administrativa: 
    ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'AdminSecure_2026!';
FLUSH PRIVILEGES;
  3. Sal de la consola y demuestra mediante captura que intentar acceder sin clave (mysql -u root) devuelve el error Error 1045 (28000): Access denied.

Actividad 11: Configuración de Herramientas Cliente en conf.d/ CE 2.d

Crea el fichero de opciones cliente globales /etc/mysql/conf.d/99-client-custom.cnf:

[client]
default-character-set = utf8mb4

[mysql]
prompt = "[\u@\h (\d)]> "
safe-updates

[mysqldump]
quick
max_allowed_packet = 32M
  1. Inicia sesión con mysql -u root -p y comprueba cómo el prompt interactivo refleja dinámicamente la base de datos seleccionada (ej. tras ejecutar USE mysql;).
  2. Intenta lanzar DELETE FROM mysql.user; y documenta la captura donde safe-updates bloquea la sentencia arrojando el Error 1175.

Actividad 12: Configuración de Cliente a Nivel de Usuario del SO (~/.my.cnf) CE 2.d, 2.h

  1. En la carpeta personal del alumno (~), crea el archivo ~/.my.cnf: 
    [client]
user = root
password = AdminSecure_2026!

[mysql]
pager = less -SFX
  2. Aplica los permisos obligatorios de seguridad: 
    chmod 600 ~/.my.cnf
  3. Demuestra que ahora puedes escribir mysql en la terminal y acceder directamente sin tener que teclear usuario ni clave.
  4. Pregunta: ¿Por qué MySQL muestra una advertencia o ignora el archivo si se le asignan permisos 644?

Actividad 13: Latencia y Análisis del Slow Log CE 2.e, 2.h

  1. Ejecuta secuencialmente desde el cliente MySQL: 
    SELECT NOW(), SLEEP(3);
SELECT NOW();
  2. Abre el fichero /var/log/mysql/slow_querys.log con sudo tail -n 15.
  3. Aporta una captura del bloque de la consulta registrada y explica técnicamente el significado de:
    • Query_time
    • Lock_time
    • Rows_sent
    • Rows_examined
  4. ¿Por qué la segunda consulta (SELECT NOW();) no se ha registrado en el archivo?

Actividad 14: Persistencia Dinámica en Caliente (mysqld-auto.cnf) CE 2.g, 2.h

  1. Ajusta en caliente y persiste el límite de conexiones concurrentes sin reiniciar: 
    SET PERSIST max_connections = 250;
  2. Inspecciona el fichero físico generado en Linux: 
    sudo cat /var/lib/mysql/mysqld-auto.cnf
    Aporta captura del archivo JSON generado internamente por MySQL 8.x.
  3. Devuelve la variable a su estado original: 
    RESET PERSIST max_connections;

Actividad 15: Auditoría y Diagnóstico con performance_schema CE 2.h

  1. Provoca deliberadamente un error de sintaxis o de objeto inexistente: 
    SELECT * FROM base_inexistente.tabla_falsa;
    Apunta el código numérico producido (ej. Error 1146).
  2. Consulta los errores registrados en el catálogo para el usuario root: 
    SELECT * FROM performance_schema.events_errors_summary_by_user_by_error 
WHERE USER = 'root' AND COUNT_STAR > 0;
    Aporta captura donde se aprecie el error reflejado en COUNT_STAR.
  3. Consulta el total de operaciones de lectura realizadas por el usuario activo: 
    SELECT * FROM performance_schema.status_by_user 
WHERE USER = 'root' AND VARIABLE_NAME LIKE 'Handler_read%';
