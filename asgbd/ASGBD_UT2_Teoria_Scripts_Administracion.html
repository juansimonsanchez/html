1. Repaso Teórico: Programación en MySQL¶

La administración moderna de bases de datos no se limita a ejecutar consultas interactivas. Para garantizar la eficiencia, seguridad y automatización, los SGBD permiten compilar y ejecutar lógica programada directamente en el servidor a través de procedimientos, funciones, cursores y disparadores.

1.1. Directivas Básicas y Tipos de Variables ¶

  • Delimitador de Sentencias (DELIMITER): En MySQL, el terminador por defecto es el punto y coma (;). Al programar bloques de código con múltiples instrucciones internas, es obligatorio redefinir temporalmente este separador (habitualmente mediante // o //) para que el analizador no divida la rutina prematuramente.

  • Variables Locales (DECLARE): Se definen exclusivamente dentro de bloques BEGIN ... END de rutinas o disparadores. Su ciclo de vida concluye al finalizar dicho bloque. Regla de sintaxis estricta: deben ubicarse siempre al principio del bloque, antes de cualquier declaración de cursor o manejador de errores (HANDLER).

  • Variables de Sesión de Usuario: Llevan como prefijo la arroba (@nombre). No requieren definición de tipo explícita y su valor permanece en memoria mientras la conexión del cliente con el motor continúe activa.

  • Variables del Sistema: Regulan los parámetros operativos de MySQL. Pueden tener alcance global (@@GLOBAL.variable) o de sesión (@@SESSION.variable).

Ejemplo 1.1.A (Sencillo): Comparativa de ámbito entre variables locales y de sesión

-- Variable de sesión de usuario (visible durante toda la conexión actual)
SET @iva_reducido = 0.10;

DROP PROCEDURE IF EXISTS sp_calcular_pvp;
DELIMITER //
CREATE PROCEDURE sp_calcular_pvp(IN p_base DECIMAL(10,2))
BEGIN
  -- Variable local: solo accesible dentro de este bloque BEGIN...END
  DECLARE v_impuesto DECIMAL(10,2);

  SET v_impuesto = p_base * @iva_reducido;
  SELECT p_base AS 'Base', v_impuesto AS 'Cuota IVA', (p_base + v_impuesto) AS 'PVP';
END //
DELIMITER ;

CALL sp_calcular_pvp(100.00);

Ejemplo 1.1.B (Complejo): Captura, alteración temporal y restauración de variables del sistema

DROP PROCEDURE IF EXISTS sp_admin_ajuste_carga_masiva;
DELIMITER //
CREATE PROCEDURE sp_admin_ajuste_carga_masiva()
BEGIN
  -- 1. Respaldar variables de sesión en variables locales
  DECLARE v_fk_original INT;
  DECLARE v_autocommit_original INT;

  SET v_fk_original = @@SESSION.foreign_key_checks;
  SET v_autocommit_original = @@SESSION.autocommit;

  -- 2. Desactivar temporalmente restricciones para maximizar throughput de carga
  SET SESSION foreign_key_checks = 0;
  SET SESSION autocommit = 0;

  -- [Inserciones masivas / Procesamiento batch]

  -- 3. Restaurar íntegramente la configuración original de la sesión
  SET SESSION foreign_key_checks = v_fk_original;
  SET SESSION autocommit = v_autocommit_original;
END //
DELIMITER ;

1.2. Procedimientos Almacenados (Stored Procedures) ¶

Son subprogramas que se compilan y almacenan en el SGBD. Permiten implementar operaciones complejas, modificar registros en múltiples tablas y ejecutar sentencias DDL (Data Definition Language) de forma dinámica.

  • Parámetros:

    • IN (Entrada): El valor entra a la rutina pero no puede devolver cambios al exterior (paso por valor).

    • OUT (Salida): La rutina asigna un valor a este parámetro para devolverlo al invocador (paso por referencia).

    • INOUT (Entrada/Salida): Entra con un valor inicial y sale con el valor resultante transformado por la rutina.

  • Invocación: Se ejecutan mediante la instrucción CALL nombre_procedimiento(parámetros);.

  • Asignación de datos: Para volcar resultados en variables se utiliza tanto SET variable = (SELECT ...) como la cláusula SELECT col INTO variable FROM ....

  • Uso Administrativo: Creación masiva de cuentas, particionamiento, mantenimiento programado y reorganización de índices.

Ejemplo 1.2.A (Sencillo): Conteo de jugadores por equipo con parámetro de salida OUT y SELECT INTO (Base de datos liga)

USE liga;

DROP PROCEDURE IF EXISTS sp_contar_jugadores_equipo;
DELIMITER //
CREATE PROCEDURE sp_contar_jugadores_equipo(
  IN p_id_equipo INT UNSIGNED,
  OUT p_total INT UNSIGNED
)
BEGIN
  -- Conteo de plantilla asignada a un club determinado
  SELECT COUNT(*) INTO p_total
  FROM jugadores
  WHERE id_equipo = p_id_equipo;
END //
DELIMITER ;

-- Invocación pasando variable de usuario para recoger el resultado (ej. equipo 1)
CALL sp_contar_jugadores_equipo(1, @total_jugadores);
SELECT @total_jugadores AS 'Total Jugadores Equipo 1';

Ejemplo 1.2.B (Complejo): Cálculo estadístico agregado de almacenamiento por esquema con múltiples parámetros

DROP PROCEDURE IF EXISTS sp_admin_metricas_espacio_esquema;
DELIMITER //
CREATE PROCEDURE sp_admin_metricas_espacio_esquema(
  IN p_esquema VARCHAR(64),
  OUT p_total_tablas INT,
  OUT p_espacio_mb DECIMAL(12,2),
  OUT p_tabla_mas_pesada VARCHAR(64)
)
BEGIN
  -- Obtener número de tablas y peso total en MB en una sola consulta
  SELECT
    COUNT(*),
    IFNULL(ROUND(SUM(data_length + index_length) / 1024 / 1024, 2), 0.00)
  INTO p_total_tablas, p_espacio_mb
  FROM information_schema.tables
  WHERE table_schema = p_esquema AND table_type = 'BASE TABLE';

  -- Determinar la tabla con mayor volumen ocupado
  SELECT table_name INTO p_tabla_mas_pesada
  FROM information_schema.tables
  WHERE table_schema = p_esquema AND table_type = 'BASE TABLE'
  ORDER BY (data_length + index_length) DESC
  LIMIT 1;
END //
DELIMITER ;

CALL sp_admin_metricas_espacio_esquema('mysql', @total, @mb, @mayor_tabla);
SELECT @total AS 'Tablas', @mb AS 'Megabytes', @mayor_tabla AS 'Tabla Mayor';

1.3. Funciones Almacenadas (Stored Functions) ¶

A diferencia de los procedimientos, las funciones están diseñadas específicamente para calcular y devolver un único valor escalar (numérico, texto, fecha).

  • Todos los parámetros recibidos son obligatoriamente de entrada (no se coloca la palabra IN).

  • Deben especificar el tipo de dato que retornan mediante RETURNS tipo_dato y finalizar con RETURN valor;.

  • Restricción Binaria / Determinismo: Es obligatorio indicar al menos una de sus cláusulas de comportamiento: DETERMINISTIC, NO SQL o READS SQL DATA (para evitar el error 1418 cuando el binary logging está habilitado). Opcionalmente el administrador puede fijar en el servidor SET GLOBAL log_bin_trust_function_creators = 1;.

  • No admiten control de transacciones explícito (COMMIT / ROLLBACK) ni manipulación directa de tablas en consultas estándar.

  • Se integran directamente dentro de sentencias SQL estándar (SELECT funcion(...), WHERE, ORDER BY).

Ejemplo 1.3.A (Sencillo): Función escalar de conversión de unidades

DROP FUNCTION IF EXISTS fn_bytes_a_gigabytes;
DELIMITER //
CREATE FUNCTION fn_bytes_a_gigabytes(p_bytes BIGINT)
RETURNS DECIMAL(10,3)
DETERMINISTIC
NO SQL
BEGIN
  RETURN ROUND(p_bytes / 1024 / 1024 / 1024, 3);
END //
DELIMITER ;

-- Invocación en una consulta administrativa ordinaria
SELECT table_name, fn_bytes_a_gigabytes(data_length) AS 'Datos_GB'
FROM information_schema.tables
WHERE table_schema = 'mysql'
LIMIT 5;

Ejemplo 1.3.B (Complejo): Saneamiento y normalización de identificadores

DROP FUNCTION IF EXISTS fn_sanitizar_identificador;
DELIMITER //
CREATE FUNCTION fn_sanitizar_identificador(p_texto VARCHAR(255))
RETURNS VARCHAR(255)
DETERMINISTIC
NO SQL
BEGIN
  DECLARE v_resultado VARCHAR(255);

  -- Normalizar a minúsculas y sustituir tildes
  SET v_resultado = LOWER(p_texto);
  SET v_resultado = REPLACE(v_resultado, 'á', 'a');
  SET v_resultado = REPLACE(v_resultado, 'é', 'e');
  SET v_resultado = REPLACE(v_resultado, 'í', 'i');
  SET v_resultado = REPLACE(v_resultado, 'ó', 'o');
  SET v_resultado = REPLACE(v_resultado, 'ú', 'u');
  SET v_resultado = REPLACE(v_resultado, ' ', '_');
  -- Eliminar cualquier carácter que no sea alfanumérico o guion bajo
  SET v_resultado = REGEXP_REPLACE(v_resultado, '[^a-z0-9_]', '');

  RETURN v_resultado;
END //
DELIMITER ;

SELECT fn_sanitizar_identificador('Copia Seguridad_Producción 2026!') AS 'Identificador_Valido';

1.4. Estructuras de Control de Flujo (Condicionales y Bucles) ¶

Permiten alterar el flujo secuencial de ejecución dentro de rutinas almacenadas:

  • Condicionales:

    • IF ... THEN ... [ELSEIF ... THEN ...] [ELSE ...] END IF;
    • CASE ... WHEN ... THEN ... [ELSE ...] END CASE; (permite comparar valores o evaluar condiciones booleanas).

  • Bucles e Iteraciones:

    • WHILE condición DO ... END WHILE; (evaluación previa a cada ciclo).
    • REPEAT ... UNTIL condición END REPEAT; (ejecución garantizada de al menos un ciclo hasta cumplirse la condición).
    • LOOP ... END LOOP; (bucle indefinido con etiquetas; requiere LEAVE etiqueta; para romper o ITERATE etiqueta; para continuar).

Ejemplo 1.4.A: Clasificación condicional con IF / ELSEIF (Base de datos liga)

Evalúa el salario asignado a un jugador en la tabla jugadores y lo cataloga en una escala salarial:

USE liga;

DROP PROCEDURE IF EXISTS sp_evaluar_salario_jugador;
DELIMITER //
CREATE PROCEDURE sp_evaluar_salario_jugador(
  IN p_id_jugador INT UNSIGNED,
  OUT p_categoria VARCHAR(30)
)
BEGIN
  DECLARE v_salario INT UNSIGNED;

  SELECT salario INTO v_salario
  FROM jugadores
  WHERE id_jugador = p_id_jugador;

  IF v_salario IS NULL THEN
    SET p_categoria = 'SIN ASIGNAR';
  ELSEIF v_salario < 100000 THEN
    SET p_categoria = 'SALARIO BASE';
  ELSEIF v_salario BETWEEN 100000 AND 300000 THEN
    SET p_categoria = 'SALARIO MEDIO';
  ELSE
    SET p_categoria = 'SALARIO ESTRELLA';
  END IF;
END //
DELIMITER ;

CALL sp_evaluar_salario_jugador(1, @cat);
SELECT @cat AS 'Escala Salarial Jugador 1';

Ejemplo 1.4.B: Bucle WHILE (Evaluación Previa) sobre la base de datos liga

Calcula el gasto salarial acumulado de los primeros N equipos registrados en la tabla equipos recorriendo ordenadamente sus identificadores correlativos:

USE liga;

DROP PROCEDURE IF EXISTS sp_acumular_salarios_while;
DELIMITER //
CREATE PROCEDURE sp_acumular_salarios_while(
  IN p_max_equipos INT,
  OUT p_gasto_total DECIMAL(14,2)
)
BEGIN
  DECLARE v_contador INT DEFAULT 1;
  DECLARE v_salarios_equipo DECIMAL(14,2);

  SET p_gasto_total = 0.00;

  -- Bucle WHILE: se comprueba la condición al inicio de cada iteración
  WHILE v_contador <= p_max_equipos DO
    SELECT IFNULL(SUM(salario), 0) INTO v_salarios_equipo
    FROM jugadores
    WHERE id_equipo = v_contador;

    SET p_gasto_total = p_gasto_total + v_salarios_equipo;
    SET v_contador = v_contador + 1;
  END WHILE;
END //
DELIMITER ;

CALL sp_acumular_salarios_while(3, @total_salarios);
SELECT @total_salarios AS 'Gasto Salarial Equipos 1 al 3';

Ejemplo 1.4.C: Bucle LOOP con LEAVE e ITERATE sobre la base de datos liga

Recorre una serie de identificadores de equipos insertando en una tabla temporal el balance de puntos como local (puntos anotados a favor frente a puntos recibidos en contra), utilizando ITERATE para omitir equipos exentos y LEAVE para salir del bucle indefinido:

USE liga;

DROP PROCEDURE IF EXISTS sp_balance_local_loop;
DELIMITER //
CREATE PROCEDURE sp_balance_local_loop(IN p_limite_equipos INT)
BEGIN
  DECLARE v_id INT DEFAULT 0;
  DECLARE v_puntos_favor INT;
  DECLARE v_puntos_contra INT;

  -- Tabla temporal para almacenar resultados
  CREATE TEMPORARY TABLE IF NOT EXISTS tmp_balance_equipos (
    id_equipo INT,
    nombre_equipo VARCHAR(50),
    diferencia_puntos INT
  );
  TRUNCATE TABLE tmp_balance_equipos;

  bucle_equipos: LOOP
    SET v_id = v_id + 1;

    -- Condición de parada y ruptura del ciclo mediante LEAVE
    IF v_id > p_limite_equipos THEN
      LEAVE bucle_equipos;
    END IF;

    -- Ejemplo de ITERATE: omitir el equipo con id = 2 en el procesamiento
    IF v_id = 2 THEN
      ITERATE bucle_equipos;
    END IF;

    -- Cálculo del balance de puntos del equipo cuando jugó como local
    SELECT
      IFNULL(SUM(puntos_local), 0),
      IFNULL(SUM(puntos_visitante), 0)
    INTO v_puntos_favor, v_puntos_contra
    FROM partidos
    WHERE elocal = v_id;

    INSERT INTO tmp_balance_equipos (id_equipo, nombre_equipo, diferencia_puntos)
    SELECT id_equipo, nombre, (v_puntos_favor - v_puntos_contra)
    FROM equipos
    WHERE id_equipo = v_id;

  END LOOP bucle_equipos;

  SELECT * FROM tmp_balance_equipos;
END //
DELIMITER ;

CALL sp_balance_local_loop(4);

Ejemplo 1.4.D: Bucle REPEAT ... UNTIL (Evaluación Posterior) sobre la base de datos liga

Ejecuta el bloque de sentencias al menos una vez y evalúa la condición de finalización al cierre. En este caso, suma las alturas de los jugadores de un equipo hasta alcanzar o superar un umbral de altura acumulada en metros o agotar el listado:

USE liga;

DROP PROCEDURE IF EXISTS sp_sumar_alturas_repeat;
DELIMITER //
CREATE PROCEDURE sp_sumar_alturas_repeat(
  IN p_id_equipo INT UNSIGNED,
  IN p_umbral_altura DECIMAL(5,2),
  OUT p_altura_acumulada DECIMAL(5,2),
  OUT p_jugadores_procesados INT
)
BEGIN
  DECLARE v_offset INT DEFAULT 0;
  DECLARE v_altura_actual DECIMAL(3,2);
  DECLARE v_total_en_plantilla INT;

  SET p_altura_acumulada = 0.00;
  SET p_jugadores_procesados = 0;

  SELECT COUNT(*) INTO v_total_en_plantilla
  FROM jugadores
  WHERE id_equipo = p_id_equipo AND altura IS NOT NULL;

  -- Bucle REPEAT: se ejecuta siempre al menos una vez hasta que UNTIL sea verdadero
  REPEAT
    SELECT altura INTO v_altura_actual
    FROM jugadores
    WHERE id_equipo = p_id_equipo AND altura IS NOT NULL
    ORDER BY altura DESC
    LIMIT 1 OFFSET v_offset;

    SET p_altura_acumulada = p_altura_acumulada + v_altura_actual;
    SET p_jugadores_procesados = p_jugadores_procesados + 1;
    SET v_offset = v_offset + 1;

  UNTIL (p_altura_acumulada >= p_umbral_altura OR v_offset >= v_total_en_plantilla)
  END REPEAT;
END //
DELIMITER ;

CALL sp_sumar_alturas_repeat(1, 4.00, @altura_total, @num_jugadores);
SELECT @altura_total AS 'Altura Acumulada (m)', @num_jugadores AS 'Jugadores Evaluados';

1.5. Cursores (Procesamiento Secuencial de Filas) ¶

Los cursores permiten recorrer individualmente el conjunto de filas resultante de una consulta SELECT. En MySQL son de sólo lectura (read-only) y unidireccionales (non-scrollable).

Requieren completar cuatro fases obligatorias:

  1. DECLARE cursor_name CURSOR FOR sentencia_select; (declarados tras las variables y antes de los handlers).
  2. OPEN cursor_name; (materializa el conjunto de resultados e inicializa el puntero).
  3. FETCH cursor_name INTO var1, var2, ...; (recupera los valores de la fila actual y desplaza el cursor).
  4. CLOSE cursor_name; (libera los recursos del servidor).

El agotamiento del cursor se controla capturando la condición NOT FOUND (SQLSTATE '02000'):

Ejemplo 1.5.A (Sencillo): Recorrido con cursor e impresión diagnóstica

DROP PROCEDURE IF EXISTS sp_listar_esquemas_usuario;
DELIMITER //
CREATE PROCEDURE sp_listar_esquemas_usuario()
BEGIN
  DECLARE v_fin INT DEFAULT FALSE;
  DECLARE v_schema_name VARCHAR(64);

  DECLARE cur_db CURSOR FOR
    SELECT schema_name FROM information_schema.schemata
    WHERE schema_name NOT IN ('information_schema', 'mysql', 'performance_schema', 'sys');

  DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_fin = TRUE;

  OPEN cur_db;
  bucle_db: LOOP
    FETCH cur_db INTO v_schema_name;
    IF v_fin THEN
      LEAVE bucle_db;
    END IF;

    SELECT CONCAT('Esquema detectado: ', v_schema_name) AS 'Mensaje';
  END LOOP bucle_db;
  CLOSE cur_db;
END //
DELIMITER ;

Ejemplo 1.5.B (Complejo): Verificación física masiva de tablas (CHECK TABLE) con DDL dinámico

DROP PROCEDURE IF EXISTS sp_admin_auditar_tablas_esquema;
DELIMITER //
CREATE PROCEDURE sp_admin_auditar_tablas_esquema(IN p_esquema VARCHAR(64))
BEGIN
  DECLARE v_done INT DEFAULT FALSE;
  DECLARE v_tabla VARCHAR(64);

  DECLARE cur_revision CURSOR FOR
    SELECT table_name
    FROM information_schema.tables
    WHERE table_schema = p_esquema AND table_type = 'BASE TABLE';

  DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;

  OPEN cur_revision;
  revision_loop: LOOP
    FETCH cur_revision INTO v_tabla;
    IF v_done THEN
      LEAVE revision_loop;
    END IF;

    -- Construir y ejecutar la comprobación de integridad estructural
    SET @sql_check = CONCAT('CHECK TABLE `', p_esquema, '`.`', v_tabla, '` EXTENDED;');
    PREPARE stmt FROM @sql_check;
    EXECUTE stmt;
    DEALLOCATE PREPARE stmt;
  END LOOP revision_loop;
  CLOSE cur_revision;
END //
DELIMITER ;

1.6. Control de Excepciones (Handlers) y Transacciones ¶

MySQL permite capturar incidencias en tiempo de ejecución mediante DECLARE ... HANDLER:

  • Acción del manejador: CONTINUE (ejecuta el bloque del handler y prosigue con la instrucción siguiente) o EXIT (ejecuta el handler y finaliza el bloque BEGIN...END).
  • Condiciones capturadas: Código numérico nativo de MySQL (ej. 1062 por clave duplicada), valor SQLSTATE (ej. '23000'), o clasificadores generales como SQLEXCEPTION o SQLWARNING.
  • Garantía transaccional: La unión de handlers con transacciones asegura la atomicidad en operaciones de riesgo.

Ejemplo 1.6.A (Sencillo): Captura de clave primaria duplicada con CONTINUE HANDLER

DROP PROCEDURE IF EXISTS sp_insertar_ip_whitelist;
DELIMITER //
CREATE PROCEDURE sp_insertar_ip_whitelist(IN p_ip VARCHAR(45), OUT p_estado VARCHAR(50))
BEGIN
  -- Manejar error 1062 (Duplicate entry) para no interrumpir el flujo
  DECLARE CONTINUE HANDLER FOR 1062
  BEGIN
    SET p_estado = 'DUPLICADA_IGNORADA';
  END;

  SET p_estado = 'INSERTADA_OK';
  INSERT INTO red_ips_autorizadas(ip) VALUES (p_ip);
END //
DELIMITER ;

Ejemplo 1.6.B (Complejo): Transacción atómica con rollback forzado y comprobación de filas afectadas

DROP PROCEDURE IF EXISTS sp_admin_traspaso_fondos;
DELIMITER //
CREATE PROCEDURE sp_admin_traspaso_fondos(
  IN p_origen INT,
  IN p_destino INT,
  IN p_cantidad DECIMAL(10,2),
  OUT p_resultado VARCHAR(100)
)
BEGIN
  -- Ante cualquier excepción SQL general, revertir cambios y abortar
  DECLARE EXIT HANDLER FOR SQLEXCEPTION
  BEGIN
    ROLLBACK;
    SET p_resultado = 'FALLO CRÍTICO: Error en el motor, ROLLBACK efectuado.';
  END;

  START TRANSACTION;
    -- Restar saldo validando suficiencia
    UPDATE cuentas_bancarias
    SET saldo = saldo - p_cantidad
    WHERE id_cuenta = p_origen AND saldo >= p_cantidad;

    -- Validar si la cuenta de origen tenía saldo suficiente
    IF ROW_COUNT() = 0 THEN
      ROLLBACK;
      SET p_resultado = 'ERROR: Saldo insuficiente o cuenta origen inexistente.';
    ELSE
      -- Ingresar fondos en cuenta destino
      UPDATE cuentas_bancarias
      SET saldo = saldo + p_cantidad
      WHERE id_cuenta = p_destino;

      COMMIT;
      SET p_resultado = 'OPERACIÓN EXITOSA: Transacción confirmada (COMMIT).';
    END IF;
END //
DELIMITER ;

1.7. Disparadores (Triggers) ¶

Un disparador es un bloque de código asociado a una tabla que se activa automáticamente en respuesta a un evento DML (INSERT, UPDATE o DELETE).

  • Momento de ejecución:

    • BEFORE: Previo a la validación e inserción en la tabla (apropiado para normalización de datos y validaciones de rango).
    • AFTER: Posterior a la consolidación de la operación (ideal para pistas de auditoría y replicación lógica de datos).

  • Variables de registro:

    • OLD: Estado previo del registro (disponible en UPDATE y DELETE).
    • NEW: Nuevo estado proyectado (disponible en INSERT y UPDATE; modificable en eventos BEFORE).

Ejemplo 1.7.A (Sencillo): Normalización y ajuste de campos en BEFORE INSERT

DROP TRIGGER IF EXISTS tg_usuarios_formatear_credenciales;
DELIMITER //
CREATE TRIGGER tg_usuarios_formatear_credenciales
BEFORE INSERT ON usuarios_portal
FOR EACH ROW
BEGIN
  -- Forzar correo electrónico en minúsculas y sin espacios
  SET NEW.email = LOWER(TRIM(NEW.email));
  -- Corregir cuotas de almacenamiento anómalas
  IF NEW.cuota_disco_mb "<" 0 THEN
    SET NEW.cuota_disco_mb = 100;
  END IF;
END //
DELIMITER ;

Ejemplo 1.7.B (Complejo): Auditoría forense de cambios de privilegios en AFTER UPDATE

CREATE TABLE IF NOT EXISTS log_auditoria_seguridad (
  id INT AUTO_INCREMENT PRIMARY KEY,
  id_afectado INT,
  nivel_anterior VARCHAR(30),
  nivel_nuevo VARCHAR(30),
  usuario_modificador VARCHAR(100),
  host_origen VARCHAR(100),
  fecha_modificacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

DROP TRIGGER IF EXISTS tg_auditoria_roles_usuarios;
DELIMITER //
CREATE TRIGGER tg_auditoria_roles_usuarios
AFTER UPDATE ON administradores_sistema
FOR EACH ROW
BEGIN
  -- Auditar únicamente cuando exista un cambio real de rol o permisos
  IF OLD.nivel_acceso != NEW.nivel_acceso THEN
    INSERT INTO log_auditoria_seguridad (
      id_afectado,
      nivel_anterior,
      nivel_nuevo,
      usuario_modificador,
      host_origen,
      fecha_modificacion
    ) VALUES (
      OLD.id,
      OLD.nivel_acceso,
      NEW.nivel_acceso,
      USER(),
      CURRENT_USER(),
      NOW()
    );
  END IF;
END //
DELIMITER ;

1.8. Casos Prácticos de Mantenimiento y Administración mediante Rutinas y Triggers ¶

En el trabajo cotidiano de un Administrador de Sistemas de Bases de Datos (DBA), los procedimientos, funciones y disparadores no se limitan a cálculos matemáticos; resuelven problemas de optimización física del almacenamiento, saneamiento por lotes y blindaje de seguridad interna:

Caso 1 (Procedimiento): Desfragmentación y Optimización Masiva de Tablas

Tras grandes operaciones de borrado o actualización, el espacio en disco queda fragmentado en los motores de almacenamiento (como InnoDB o MyISAM). Este procedimiento utiliza un cursor sobre el catálogo information_schema.tables y construye consultas preparadas dinámicas (PREPARE / EXECUTE) para desfragmentar de forma consecutiva todas las tablas de una base de datos específica:

DELIMITER //
DROP PROCEDURE IF EXISTS sp_admin_optimizar_tablas//
CREATE PROCEDURE sp_admin_optimizar_tablas(IN p_esquema VARCHAR(64))
BEGIN
  DECLARE v_fin INT DEFAULT FALSE;
  DECLARE v_tabla VARCHAR(64);
  -- Cursor que recupera todas las tablas físicas del esquema indicado
  DECLARE cur_tablas CURSOR FOR
    SELECT table_name
    FROM information_schema.tables
    WHERE table_schema = p_esquema AND table_type = 'BASE TABLE';
  DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_fin = TRUE;

  OPEN cur_tablas;
  bucle_tablas: LOOP
    FETCH cur_tablas INTO v_tabla;
    IF v_fin THEN
      LEAVE bucle_tablas;
    END IF;

    -- Construcción y ejecución de la sentencia DDL de mantenimiento
    SET @sql_opt = CONCAT('OPTIMIZE TABLE `', p_esquema, '`.`', v_tabla, '`;');
    PREPARE stmt FROM @sql_opt;
    EXECUTE stmt;
    DEALLOCATE PREPARE stmt;
  END LOOP;
  CLOSE cur_tablas;
END //
DELIMITER ;

Caso 2 (Procedimiento): Purga Masiva Segura sin Bloqueo de Transacciones

Ejecutar un DELETE FROM logs WHERE fecha < ... directo sobre tablas con millones de filas bloquea los recursos del servidor y llena el buffer del log de transacciones. La buena práctica consiste en realizar el borrado en lotes acotados (chunks) mediante un bucle WHILE con LIMIT y aplicando COMMIT tras cada bloque:

DELIMITER //
DROP PROCEDURE IF EXISTS sp_admin_purgar_logs_por_lotes//
CREATE PROCEDURE sp_admin_purgar_logs_por_lotes(
  IN p_dias_retencion INT,
  IN p_tamano_lote INT,
  OUT p_total_eliminados INT
)
BEGIN
  DECLARE v_filas_afectadas INT DEFAULT 1;
  SET p_total_eliminados = 0;

  -- Itera eliminando bloques pequeños hasta vaciar el histórico obsoleto
  WHILE v_filas_afectadas > 0 DO
    DELETE FROM auditoria_sistema
    WHERE fecha_evento < NOW() - INTERVAL p_dias_retencion DAY
    LIMIT p_tamano_lote;

    -- Obtiene cuántas filas se eliminaron en el lote actual
    SET v_filas_afectadas = ROW_COUNT();
    SET p_total_eliminados = p_total_eliminados + v_filas_afectadas;

    -- Confirma la transacción para liberar bloqueos y memoria
    COMMIT;
  END WHILE;
END //
DELIMITER ;

Caso 3 (Procedimiento): Rotación y Archivado Dinámico de Tablas

Para mantener contenidas las tablas de alto volumen (ej. pedidos antiguos), este procedimiento crea dinámicamente una tabla de histórico identificada por año (si no existiera previamente), traslada los datos cerrados y purga la tabla en producción dentro de una transacción atómica:

DELIMITER //
DROP PROCEDURE IF EXISTS sp_admin_archivar_historico_anual//
CREATE PROCEDURE sp_admin_archivar_historico_anual(IN p_anio INT)
BEGIN
  DECLARE EXIT HANDLER FOR SQLEXCEPTION
  BEGIN
    ROLLBACK;
    RESIGNAL;
  END;

  -- 1. Crear la tabla destino histórica del año correspondiente
  SET @tabla_historica = CONCAT('pedidos_historico_', p_anio);
  SET @sql_crear = CONCAT('CREATE TABLE IF NOT EXISTS `', @tabla_historica, '` LIKE pedidos;');
  PREPARE stmt1 FROM @sql_crear;
  EXECUTE stmt1;
  DEALLOCATE PREPARE stmt1;

  -- 2. Transacción de volcado y purga atómica
  START TRANSACTION;
    SET @sql_volcar = CONCAT('INSERT INTO `', @tabla_historica, '` SELECT * FROM pedidos WHERE YEAR(fecha_pedido) = ', p_anio, ';');
    PREPARE stmt2 FROM @sql_volcar;
    EXECUTE stmt2;
    DEALLOCATE PREPARE stmt2;

    SET @sql_borrar = CONCAT('DELETE FROM pedidos WHERE YEAR(fecha_pedido) = ', p_anio, ';');
    PREPARE stmt3 FROM @sql_borrar;
    EXECUTE stmt3;
    DEALLOCATE PREPARE stmt3;
  COMMIT;
END //
DELIMITER ;

Caso 4 (Función): Diagnóstico de Fragmentación y Espacio No Reclamado

Los administradores necesitan supervisar qué tablas contienen un alto índice de espacio libre residual (Data Free) para planificar ventanas de mantenimiento. Esta función consulta el diccionario de datos y devuelve el porcentaje de espacio desperdiciado sobre el tamaño total de la tabla:

DELIMITER //
DROP FUNCTION IF EXISTS fn_admin_ratio_fragmentacion//
CREATE FUNCTION fn_admin_ratio_fragmentacion(
  p_esquema VARCHAR(64),
  p_tabla VARCHAR(64)
)
RETURNS DECIMAL(5,2)
READS SQL DATA
BEGIN
  DECLARE v_data_bytes BIGINT;
  DECLARE v_free_bytes BIGINT;
  DECLARE v_ratio DECIMAL(5,2) DEFAULT 0.00;

  SELECT (data_length + index_length), data_free
  INTO v_data_bytes, v_free_bytes
  FROM information_schema.tables
  WHERE table_schema = p_esquema AND table_name = p_tabla;

  -- Si la tabla tiene datos y espacio libre detectado
  IF (v_data_bytes + v_free_bytes) > 0 THEN
    SET v_ratio = (v_free_bytes / (v_data_bytes + v_free_bytes)) * 100;
  END IF;

  RETURN ROUND(v_ratio, 2);
END //
DELIMITER ;

Caso 5 (Función): Verificación de Existencia de Privilegios Administrativos

Antes de lanzar despliegues automatizados, es recomendable verificar si una cuenta posee permisos específicos. Esta función consulta la tabla física mysql.user y devuelve un booleano confirmando si el usuario dispone o no de privilegios globales de administración (ej. SUPER o Process_priv):

DELIMITER //
DROP FUNCTION IF EXISTS fn_admin_es_administrador//
CREATE FUNCTION fn_admin_es_administrador(
  p_usuario VARCHAR(32),
  p_host VARCHAR(60)
)
RETURNS BOOLEAN
READS SQL DATA
BEGIN
  DECLARE v_es_admin INT DEFAULT 0;

  SELECT COUNT(*)
  INTO v_es_admin
  FROM mysql.user
  WHERE user = p_usuario
    AND host = p_host
    AND (Super_priv = 'Y' OR Process_priv = 'Y' OR Reload_priv = 'Y');

  IF v_es_admin > 0 THEN
    RETURN TRUE;
  ELSE
    RETURN FALSE;
  END IF;
END //
DELIMITER ;

Caso 6 (Disparador): Protección de Seguridad contra Borrados Accidentales

Un error grave de administración es lanzar un DELETE sin la cláusula WHERE adecuada en producción. Este disparador de tipo BEFORE DELETE consulta la identidad de ejecución o impide el borrado sobre tablas protegidas si quien lo intenta no es el administrador supremo (root@localhost), abortando la operación de inmediato con SIGNAL SQLSTATE:

DELIMITER //
DROP TRIGGER IF EXISTS tg_admin_bloqueo_borrado_critico//
CREATE TRIGGER tg_admin_bloqueo_borrado_critico
BEFORE DELETE ON configuracion_global
FOR EACH ROW
BEGIN
  -- Validar si el usuario actual es el administrador de mantenimiento
  IF USER() != 'root@localhost' THEN
    SIGNAL SQLSTATE '45000'
      SET MESSAGE_TEXT = 'ACCESO DENEGADO: La tabla de configuracion solo puede ser modificada por el administrador supremo.';
  END IF;

  -- Comprobar si se intenta borrar un parámetro marcado como bloqueado
  IF OLD.bloqueado = 1 THEN
    SIGNAL SQLSTATE '45000'
      SET MESSAGE_TEXT = 'OPERACION ABORTADA: No se permite la eliminacion de parametros del sistema con bloqueo activo.';
  END IF;
END //
DELIMITER ;

2. Ventajas de la programación en la administración ¶

El uso de estos elementos dentro del SGBD ofrece tres ventajas operativas críticas para un Administrador de Sistemas de Bases de Datos (ASGBD):

Ventaja Descripción Técnica Impacto en la Administración
Reutilización y Mantenimiento Encapsula la lógica de negocio y administración. Si un proceso de backup cambia, solo se modifica el objeto en el servidor, no las aplicaciones externas. Menor duplicación de código y reducción del error humano.
Seguridad de Acceso Permite restringir el acceso directo a tablas físicas mediante permisos GRANT EXECUTE sobre procedimientos específicos. El usuario opera la BD a través de "cajas negras" controladas.
Rendimiento de Red Reduce el tráfico de red enviando únicamente la orden CALL en lugar de miles de sentencias SQL secuenciales. Ejecuciones mucho más rápidas en redes congestionadas o entornos cloud.

3. Catálogo del Sistema (Metadatos) ¶

MySQL almacena la información sobre su propia estructura (metadatos) en esquemas específicos. Dominar estos catálogos es la herramienta más potente de un Administrador de Sistemas (SysAdmin), ya que permite auditar el servidor, monitorizar el almacenamiento y diagnosticar la degradación de rendimiento directamente mediante sentencias SQL.

3.1. information_schema (El Diccionario de Datos) ¶

Es una base de datos virtual de solo lectura definida por el estándar ANSI SQL. Actúa como el diccionario de datos del SGBD. No contiene archivos de datos físicos; en su lugar, MySQL genera sus tablas dinámicamente en memoria al consultarlas.

  • SCHEMATA: Información sobre las bases de datos existentes en el servidor (nombres, collation, etc.).

  • TABLES: Metadatos de todas las tablas físicas y vistas (motor, filas estimadas, tamaño en bytes).

  • COLUMNS: Detalle de cada columna (tipo de dato, nulabilidad, privilegios).

  • STATISTICS: Métricas de bajo nivel sobre los índices.

  • ROUTINES: Catálogo de procedimientos y funciones almacenadas.

Caso Práctico 1: Obtener el tamaño en disco de cada base de datos

Esta consulta calcula el espacio real en disco de cada base de datos (Datos + Índices) expresado en Megabytes:

SELECT
table_schema AS 'Base de Datos',
ROUND(SUM(data_length + index_length) / 1024 / 1024, 2) AS 'Tamaño total (MB)',
ROUND(SUM(data_length) / 1024 / 1024, 2) AS 'Solo Datos (MB)',
ROUND(SUM(index_length) / 1024 / 1024, 2) AS 'Solo Índices (MB)'
FROM information_schema.tables
GROUP BY table_schema
ORDER BY (SUM(data_length + index_length)) DESC;

Caso Práctico 2: Detectar tablas sin Clave Primaria (Primary Key)

La ausencia de claves primarias degrada el rendimiento de búsqueda y rompe esquemas de replicación transaccional:

SELECT
t.table_schema AS 'Base de Datos',
t.table_name AS 'Tabla sin PK'
FROM information_schema.tables t
LEFT JOIN information_schema.table_constraints tc
ON t.table_schema = tc.table_schema
AND t.table_name = tc.table_name
AND tc.constraint_type = 'PRIMARY KEY'
WHERE tc.constraint_name IS NULL
AND t.table_schema NOT IN ('information_schema', 'mysql', 'performance_schema', 'sys')
AND t.table_type = 'BASE TABLE';

3.2. Base de Datos mysql (El Repositorio de Seguridad y Privilegios) ¶

A diferencia de information_schema, la base de datos mysql contiene tablas físicas persistentes en el disco. Es el núcleo de la seguridad y el control de accesos del servidor.

  • user: Cuentas de usuario, hosts autorizados, contraseñas cifradas y privilegios globales.

  • db: Privilegios de usuarios a nivel de esquema completo.

  • tables_priv y columns_priv: Permisos granulares específicos por objeto o campo.

Caso Práctico 3: Auditoría rápida de expiración de contraseñas de usuarios

Control del ciclo de vida de credenciales para normativas de seguridad y compliance:

SELECT
user AS 'Usuario',
host AS 'Host de Origen',
password_expired AS '¿Expirada?',
password_last_changed AS 'Último cambio',
password_lifetime AS 'Días de ciclo de vida'
FROM mysql.user
WHERE ssl_type != '' OR password_expired = 'Y' OR user != 'mysql.infoschema';

3.3. Base de Datos performance_schema ¶

Se enfoca de forma estricta en el rendimiento y la instrumentación de recursos del servidor. Emplea Instrumentos (puntos de sondeo en el código fuente) y Consumidores (tablas en memoria de métricas agregadas).

  • events_statements_summary_by_digest: Estadísticas acumuladas por patrón de consulta SQL.

  • threads: Hilos de ejecución activos internos del servidor.

  • events_errors_summary_by_user_by_error: Errores provocados por cada cuenta de usuario.

Caso Práctico 4: Listar los errores más comunes provocados por los usuarios

SELECT
user AS 'Usuario',
error_number AS 'Código de Error',
error_name AS 'Nombre de Error',
sum_error_raised AS 'Veces provocado',
first_seen AS 'Primera detección',
last_seen AS 'Último registro'
FROM performance_schema.events_errors_summary_by_user_by_error
WHERE sum_error_raised > 0
ORDER BY sum_error_raised DESC;

3.4. Base de Datos sys (La Abstracción Simplificada) ¶

La complejidad de performance_schema dificulta su explotación diaria. El esquema sys proporciona vistas precalculadas y procedimientos para simplificar el diagnóstico rápido del rendimiento.

Caso Práctico 5: Identificar las consultas SQL que provocan mayor latencia

SELECT
query AS 'Sentencia SQL',
db AS 'Base de Datos',
exec_count AS 'Total Ejecuciones',
total_latency AS 'Tiempo Total acumulado',
max_latency AS 'Peor latencia registrada'
FROM sys.statement_analysis
ORDER BY total_latency DESC
LIMIT 5;

Caso Práctico 6: Encontrar tablas con lecturas completas (Full Table Scans)

Permite identificar tablas que carecen de índices adecuados o ejecutan consultas ineficientes con barridos completos:

SELECT
schemaname AS 'Base de Datos',
tablename AS 'Tabla',
scans AS 'Lecturas Completas',
rows_sel AS 'Filas devueltas'
FROM sys.schema_tables_with_full_table_scans
ORDER BY scans DESC;

5. Ejemplos Prácticos de Scripts de Administración (Sencillos y Documentados) ¶

Scripts funcionales para tareas de administración operativa y mantenimiento automatizado en Linux/MySQL:

Script 1: Comprobación de Salud del Servidor (Health Check)

#!/bin/bash
# ==============================================================================
# Script: health_check_mysql.sh
# Finalidad: Monitorizar el estado operativo del servicio MySQL y su capacidad
#            de responder a conexiones de clientes.
# ==============================================================================

# Configuración estricta de ejecución de Bash:
# -e: Aborta el script inmediatamente ante cualquier comando que falle.
# -u: Trata las variables no definidas como errores y detiene la ejecución.
# -o pipefail: El valor de retorno de una tubería (|) será el del último comando
#              que falle, evitando que errores intermedios queden ocultos.
set -euo pipefail

# ------------------------------------------------------------------------------
# 1. Carga de variables de entorno y credenciales
# ------------------------------------------------------------------------------
# Se comprueba la presencia del archivo seguro .env (habitualmente restringido con chmod 600)
if [ -f ".env" ]; then
  set -a          # Exporta automáticamente todas las variables definidas a continuación
  source .env     # Carga MYSQL_USER, MYSQL_PASSWORD, etc.
  set +a          # Desactiva la exportación automática
else
  echo "[ERROR] No existe el archivo .env. Crea uno con MYSQL_USER y MYSQL_PASSWORD." >&2
  exit 1
fi

# umask 077 garantiza que cualquier fichero temporal creado durante el script
# solo tenga permisos de lectura/escritura para el propietario (seguridad estricta).
umask 077
FECHA_LOG=$(date "+%Y-%m-%d %H:%M:%S")

echo "=== INICIANDO CONTROL DE SALUD DEL SGBD ($FECHA_LOG) ==="

# ------------------------------------------------------------------------------
# 2. Verificación del demonio de servicio con systemd
# ------------------------------------------------------------------------------
# is-active --quiet devuelve 0 si el servicio está en ejecución, o != 0 si está parado o fallido
if ! systemctl is-active --quiet mysql; then
  echo "[ALERTA] El servicio MySQL no se encuentra activo. Intentando arranque automático..."
  sudo systemctl start mysql
  # Espera preventiva de 3 segundos para permitir la inicialización de sockets y buffers
  sleep 3
fi

# ------------------------------------------------------------------------------
# 3. Comprobación de conectividad a nivel de motor (Ping con mysqladmin)
# ------------------------------------------------------------------------------
# Se utiliza MYSQL_PWD para pasar la clave de forma temporal a la llamada
# mysqladmin ping verifica que el motor responde peticiones a través del socket/puerto
if MYSQL_PWD="$MYSQL_PASSWORD" mysqladmin --user="$MYSQL_USER" ping &>/dev/null; then
  echo "[OK] MySQL está levantado, escuchando y respondiendo consultas correctamente."
else
  echo "[CRÍTICO] El proceso está activo pero no responde a 'ping' (bloqueo interno o fallo de red)."
  exit 1
fi

echo "=== CONTROL DE SALUD FINALIZADO SATISFACTORIAMENTE ==="
exit 0

Script 2: Copia de Seguridad Sencilla (Backup Automatizado)

#!/bin/bash
# ==============================================================================
# Script: backup_mysql.sh
# Finalidad: Realizar un volcado consistente (dump) de la base de datos indicada,
#            incluyendo rutinas y eventos, aplicando compresión al vuelo con gzip.
# ==============================================================================

# Opciones estrictas de depuración y control de fallos en Bash
set -euo pipefail

# ------------------------------------------------------------------------------
# 1. Carga de configuración y validación de variables de entorno
# ------------------------------------------------------------------------------
if [ -f ".env" ]; then
  set -a
  source .env
  set +a
else
  echo "[ERROR] Falta el archivo .env con las credenciales de respaldo." >&2
  exit 1
fi

# ------------------------------------------------------------------------------
# 2. Preparación del directorio destino de almacenamiento
# ------------------------------------------------------------------------------
# Crea el directorio de copias si no existe (-p evita errores si ya existe)
mkdir -p "$BACKUP_DIR"
# Restringe permisos (rwx------) para impedir accesos no autorizados a las copias
chmod 700 "$BACKUP_DIR"

# Estructura del nombre de archivo con marca de tiempo precisa (AñoMesDía_HoraMinutoSegundo)
MARCA_TIEMPO=$(date "+%Y%m%d_%H%M%S")
FICHERO_BACKUP="$BACKUP_DIR/backup_${MYSQL_DATABASE}_${MARCA_TIEMPO}.sql"

echo "Iniciando copia de seguridad de la base de datos '$MYSQL_DATABASE'..."

# ------------------------------------------------------------------------------
# 3. Ejecución del volcado físico-lógico con mysqldump
# ------------------------------------------------------------------------------
# --single-transaction : Asegura un respaldo consistente en tablas InnoDB sin bloquear lecturas/escrituras.
# --routines           : Incluye en el dump los procedimientos y funciones almacenadas.
# --events             : Incluye los eventos programados en el Event Scheduler.
MYSQL_PWD="$MYSQL_PASSWORD" mysqldump \
  --user="$MYSQL_USER" \
  --databases "$MYSQL_DATABASE" \
  --single-transaction \
  --routines \
  --events \
  > "$FICHERO_BACKUP"

# ------------------------------------------------------------------------------
# 4. Compresión del fichero resultante para optimizar espacio
# ------------------------------------------------------------------------------
# -f fuerza la compresión y reemplaza el archivo .sql por .sql.gz
gzip -f "$FICHERO_BACKUP"

echo "Copia creada correctamente y comprimida en: ${FICHERO_BACKUP}.gz"
exit 0

Script 3: Comprobación de Consumo y Limpieza de Logs

#!/bin/bash
# ==============================================================================
# Script: check_storage_and_purge.sh
# Finalidad: Auditar el tamaño en megabytes ocupado por los esquemas en el motor
#            y purgar automáticamente registros históricos si se supera un umbral.
# ==============================================================================

set -euo pipefail

# ------------------------------------------------------------------------------
# 1. Carga de parámetros y variables desde entorno
# ------------------------------------------------------------------------------
if [ -f ".env" ]; then
  set -a
  source .env
  set +a
else
  echo "[ERROR] Falta el archivo .env con las credenciales necesarias." >&2
  exit 1
fi

# Umbral de advertencia fijado en Megabytes (MB)
LIMITE_MB=500

# Consulta SQL al catálogo de metadatos para sumar el tamaño total de datos e índices
QUERY_TAMANO="SELECT ROUND(SUM(data_length + index_length) / 1024 / 1024, 2) FROM information_schema.tables;"

echo "Consultando el tamaño total ocupado en disco por las tablas del SGBD..."

# ------------------------------------------------------------------------------
# 2. Extracción de métricas mediante el cliente MySQL en modo batch
# ------------------------------------------------------------------------------
# Flags utilizados en mysql:
# -A (--no-auto-rehash): Omite autocompletado para acelerar la inicialización.
# -N (--skip-column-names): Suprime la cabecera de nombres de columnas.
# -s (--silent / implícito con -AN): Devuelve únicamente el dato numérico plano.
TAMANO_ACTUAL=$(MYSQL_PWD="$MYSQL_PASSWORD" mysql --user="$MYSQL_USER" -AN -e "$QUERY_TAMANO")

# Extraer únicamente la parte entera numérica (eliminando decimales para comparación bash)
TAMANO_ENTERO=${TAMANO_ACTUAL%.*}

echo "Tamaño de datos actual en el servidor: $TAMANO_ACTUAL MB"

# ------------------------------------------------------------------------------
# 3. Evaluación del umbral y ejecución de purga de mantenimiento
# ------------------------------------------------------------------------------
if [ "$TAMANO_ENTERO" -gt "$LIMITE_MB" ]; then
  echo "[AVISO] Se ha superado el umbral seguro de $LIMITE_MB MB (Actual: $TAMANO_ACTUAL MB)."
  echo "[MANTENIMIENTO] Procediendo a purgar datos y registros con antigüedad superior a 30 días..."

  # Sentencia SQL de borrado condicionada por fecha
  QUERY_PURGA="DELETE FROM logs_sistema.registro_eventos WHERE fecha_evento < NOW() - INTERVAL 30 DAY;"

  # Ejecución de la eliminación de registros obsoletos
  MYSQL_PWD="$MYSQL_PASSWORD" mysql --user="$MYSQL_USER" -e "$QUERY_PURGA"

  echo "Purga de registros completada con éxito."
else
  echo "[INFORMACIÓN] El espacio ocupado ($TAMANO_ACTUAL MB) está dentro de los rangos óptimos permitidos."
fi

exit 0
