UT3 - Tarea 1: Control de Acceso, Vistas y Gestión de Privilegios en la BD Liga ¶

1. DESCRIPCIÓN GENERAL. OBJETIVOS ¶

Como Administradores de Sistemas (SysAdmin), una de nuestras funciones principales es garantizar la confidencialidad de la información y aplicar el Principio del Menor Privilegio (PoLP). En esta práctica, trabajaremos sobre la base de datos Liga, la cual simula el control de una competición deportiva con tablas de jugadores, equipos y partidos.

El objetivo es doble:

  1. Diseñar capas de abstracción (Vistas) para simplificar las consultas complejas y ocultar información sensible.

  2. Crear un esquema estricto de control de accesos mediante usuarios, roles y privilegios adaptados a diferentes perfiles operativos.

2. ACTIVIDADES A REALIZAR ¶

Bloque A: Diseño e Implementación de Vistas ¶

Teniendo en cuenta que la base de datos Liga contiene (al menos) las entidades equipos, jugadores y partidos, debes implementar en SQL las siguientes vistas de consulta:

  • Vista 1 (v_jugadores_equipos): Muestra información de los jugadores (nombre, posición) junto con el nombre de su equipo (solo para aquellos jugadores que tengan equipo asignado).

  • Vista 2 (v_partidos_equipos): Muestra el listado de partidos disputados con la fecha, el nombre del equipo local, el nombre del equipo visitante y el resultado (goles de cada uno).

  • Vista 3 (v_clasificacion): Muestra la tabla de posiciones de los equipos del campeonato, visualizando el nombre del equipo y sus puntos, ordenada de mayor a menor puntuación.

  • Vista 4 (v_partidos_ciudades): Muestra información detallada de los encuentros, incluyendo nombres de los equipos rivales y la ciudad donde se disputa el partido.

  • Vista 5 (v_capitanes): Muestra de forma unívoca la lista de capitanes de cada equipo, indicando el nombre del equipo y el nombre de su respectivo capitán.

Bloque B: Creación y Gestión de Usuarios y Roles ¶

Aplica políticas de acceso basadas en perfiles de seguridad implementando las siguientes cuentas en el motor MySQL:

  1. Usuario de Consulta (user_consulta_liga): Debe poder conectarse localmente y realizar exclusivamente consultas de lectura (SELECT) en todas las tablas de la base de datos Liga.

  2. Usuario de Gestión de Plantillas (user_datos_jugadores): Debe conectarse localmente y tener permisos para consultar, insertar o modificar registros únicamente sobre la tabla jugadores. No debe poder realizar ninguna acción en equipos ni partidos.

  3. Usuario de Informes (user_vistas_liga): Debe conectarse localmente y tener acceso total de lectura exclusivamente a las 5 vistas creadas en el Bloque A. No debe tener visibilidad ni acceso a las tablas físicas subyacentes.

  4. Gestión de Delegación mediante Roles:

    • Crea un rol llamado rol_equipos_admin con privilegios completos (ALL PRIVILEGES) sobre la tabla equipos.

    • Crea un usuario llamado user_equipos_manager y asígnale el rol anterior, garantizando que el rol se active de forma automática al iniciar sesión.

    • Revocación: Ejecuta las sentencias necesarias para retirar de forma definitiva los permisos concedidos al usuario user_equipos_manager.

4. CALIFICACIÓN ¶

⚠️ IMPORTANTE: El retraso en el plazo de entrega a través de la plataforma, la entrega del documento en formatos editables no permitidos (como .docx), capturas con identificación del alumno/a o la omisión de los enlaces de las fuentes documentales utilizadas penalizará gravemente la nota o invalidará la práctica.

Se entregará un único paquete comprimido que contenga:

  1. script_liga_seguridad.sql: Script SQL limpio y completamente comentado con todas las sentencias de creación de vistas, usuarios, asignación de privilegios y revocación.

  2. Documento de Verificación (PDF): Informe técnico de capturas de pantalla que demuestren de forma inequívoca el correcto funcionamiento de la práctica:

    • Prueba de las 5 vistas mostrando resultados de consulta con éxito.

    • Pruebas de Privilegios Activos: Capturas del comando SHOW GRANTS para cada usuario.

    • Pruebas de Privilegios Bloqueados (Crítico):
Capturas que muestren cómo el sistema bloquea operaciones no autorizadas
(por ejemplo, intentar hacer un INSERT con el usuario user_consulta_liga
o consultar una tabla física con user_vistas_liga).
