1. DESCRIPCIÓN GENERAL. OBJETIVOS ¶

Como administradores de sistemas (SysAdmins) o administradores de bases de datos (DBAs), es crítico dominar las bases lógicas y físicas de cómo almacena la información nuestro SGBD y cómo podemos automatizar de forma nativa sus rutinas de mantenimiento.

Esta tarea de base está diseñada para asimilar los principios físicos de almacenamiento en disco de los motores de MySQL, dominar las herramientas estándares de línea de comandos de exportación (mysqldump, SELECT INTO OUTFILE / LOAD DATA) y aprender a activar, programar y monitorizar el planificador de eventos interno de la base de datos de manera profesional.

2. CONSIDERACIONES PREVIAS ¶

  • Entorno de Trabajo: Instancia en la nube de desarrollo o local con Ubuntu 24.04 LTS.

  • Software: MySQL Server 8.0+ instalado y activo.

  • Permisos del sistema: Es necesario poseer
privilegios de sudo en el sistema operativo Linux anfitrión y acceso
como root al servidor de base de datos MySQL.

  • Variable secure_file_priv: Antes de comenzar, comprueba en qué directorio del sistema de archivos Linux tiene tu MySQL permitido realizar exportaciones directas de archivos (/var/lib/mysql-files/ por defecto).

3. ACTIVIDADES A REALIZAR ¶

BLOQUE I: ARQUITECTURA FÍSICA, MOTORES Y COPIAS EN FRÍO ¶

Ejercicio 1: Arquitectura física de almacenamiento y Motores (MyISAM / InnoDB)

  • Crea la base de datos liga.

  • Añade una tabla de tipo MyISAM llamada tabla_myisam con campos básicos. Recuerda declarar de forma explícita ENGINE=MyISAM.

  • Añade otra tabla estándar de tipo InnoDB llamada tabla_innodb (por defecto).

  • Accede al shell del sistema operativo Linux host y localiza la ruta física donde MySQL guarda los datos en disco (/var/lib/mysql/). Documenta la diferencia estructural entre el directorio de la base de datos liga y detalla qué archivos físicos corresponden a las dos tablas creadas.

Ejercicio 2: Copias de Seguridad Físicas en Frío

  • Diseña un protocolo secuencial en la consola de comandos de Linux para realizar un respaldo completo físico y en frío de la base de datos liga.

  • Simula una catástrofe de pérdida de datos en la que borres los archivos físicos de la base de datos (con el SGBD apagado) y procede a su restauración binaria en disco. Comprueba y justifica que el servicio arranca de forma íntegra.

Ejercicio 3: Exportación/Importación de Datos Planos (SELECT INTO OUTFILE / LOAD DATA)

  • Exporta los datos de una tabla utilizando la instrucción SELECT INTO
OUTFILE en formato de texto plano delimitado por comas (.csv o .txt)
dentro del directorio permitido por el sistema.

  • Abre el archivo generado en una aplicación de hoja de cálculo (Excel o LibreOffice Calc) e incluye una captura mostrando el formato correcto de las columnas.

  • Crea una tabla vacía con la misma estructura y procede a poblarla con el archivo plano generado utilizando exclusivamente la sentencia SQL LOAD DATA.

BLOQUE II: COPIAS DE SEGURIDAD LÓGICAS Y RESTAURACIÓN ¶

Ejercicio 4: Uso avanzado de la Consola con mysqldump

  • Realiza las siguientes copias de seguridad a través de la consola del sistema operativo utilizando la herramienta mysqldump de MySQL (justifica los comandos utilizados):

    1. Exporta la tabla partidos (créala previamente en liga) de la base de datos liga (estructura y datos).

    2. Exporta la estructura y datos de la tabla partidos compactando el archivo (--compact).

    3. Exporta únicamente la estructura (DDL) de la tabla partidos omitiendo sus datos.

    4. Exporta únicamente los datos (DML en formato INSERT) omitiendo la creación de tablas.

    5. Exporta toda la base de datos liga en un archivo estructurado en formato XML.

    6. Exporta todas las tablas de liga a archivos separados en formato CSV utilizando parámetros de delimitación (--tab, etc.).

    7. Exporta la base de datos liga completa con sentencias de base de datos incluidas (--databases).

    8. Exporta la totalidad de bases de datos del servidor MySQL (--all-databases).

Ejercicio 5: Restauración lógica mediante consola y comandos internos

  • Ejecuta y documenta la restauración del respaldo completo generado de la base de datos utilizando dos vías:

    • Opción A: A través de la redirección de entrada de comandos del sistema operativo (<).

    • Opción B: Autenticado en el cliente de MySQL con la orden interactiva SOURCE o su equivalente \..

BLOQUE III: PLANIFICACIÓN DE TAREAS MEDIANTE EVENTOS (MYSQL EVENTS) ¶

Ejercicio 6: Verificación y Activación del Planificador

  • Ejecuta el comando SQL para verificar el estado actual de la variable de sistema event_scheduler. ¿Qué valor obtienes y qué significa técnicamente cada estado posible (ON, OFF, DISABLED)?

  • Si el planificador está en OFF, utiliza el comando SET GLOBAL para activarlo en caliente. Luego, verifica los procesos utilizando SHOW PROCESSLIST para confirmar la existencia del daemon event_scheduler. Explica qué información proporciona cada columna de este comando.

Ejercicio 7: Evento de Ejecución Única (AT)

  • Crea una tabla de log para pruebas:
CREATE TABLE log_eventos (id INT AUTO_INCREMENT PRIMARY KEY, mensaje
VARCHAR(100), fecha TIMESTAMP);

  • Crea un evento que se ejecute una única vez dentro de los próximos 5 minutos. El cuerpo del evento debe insertar un registro en la tabla log_eventos. Identifica si te has apoyado en una IA y qué prompt has usado.

  • Verifica su ejecución consultando la tabla de logs e inspecciona con SHOW EVENTS para comprobar que, al no tener configurado PRESERVE, el evento se ha auto-eliminado tras finalizar.

  • Crea un segundo evento de ejecución única equivalente pero habilitando de forma explícita ON COMPLETION PRESERVE. Comprueba su estado una vez transcurrido el tiempo programado.

Ejercicio 8: Evento Recurrente Básico (EVERY)

  • Crea un evento programado para ejecutarse cada 1 minuto, que comience su vigencia pasados 3 minutos desde su creación, e inserte una entrada con el mensaje "Evento recurrente" en la tabla log_eventos.

  • Transcurridos 5 minutos de su ciclo de vida, ejecuta un SHOW EVENTS para inspeccionar su estado y haz un volcado de la tabla para ver las ejecuciones periódicas.

  • Ejecuta el comando SHOW CREATE EVENT [nombre_evento] y explica técnicamente qué información detallada te proporciona su estructura.

Ejercicio 9: Evento Recurrente con Fecha de Finalización (ENDS)

  • Diseña y ejecuta un evento equivalente al anterior que actúe de forma cíclica cada minuto, pero que declare una fecha límite de finalización (ENDS) a 5 minutos vista desde su puesta en marcha. Verifica la caducidad y detención del evento en el diccionario del sistema.

Ejercicio 10: Modificación de Eventos (ALTER EVENT)

  • Realiza las operaciones necesarias para modificar el evento recurrente con solo hora de inicio de forma dinámica, asignándole ahora una fecha de inicio y una fecha de fin específicas en caliente. Verifica que los metadatos se han actualizado de forma persistente.

Ejercicio 11: Diccionarios de Sistema y Auditoría de Logs

  • Realiza una consulta SELECT * directa sobre la tabla de catálogo
INFORMATION_SCHEMA.EVENTS y compárala críticamente con los datos que
expone SHOW EVENTS. ¿Qué columnas adicionales de alto valor
administrativo localizas?

  • Accede al shell del host Linux y consulta los registros de ejecución del planificador mediante el log de errores de MySQL en el disco (/var/log/mysql/error.log). Filtra la información utilizando grep para buscar los eventos procesados.

Ejercicio 12: Práctica de Eventos Aplicados al Negocio

Completa de forma secuencial las siguientes actividades lógicas basadas en eventos:

  • A. Diseña un evento que, en un día y hora específicos, realice una copia de los datos de la tabla equipos (créala en liga previamente) en una tabla llamada equipos_temp. El evento debe limpiar previamente (TRUNCATE) cualquier dato obsoleto en la tabla destino.

  • B. Ejecuta la orden del SGBD para verificar en qué momento temporal exacto está planificada la ejecución de la tarea del apartado anterior.

  • C. Comprueba la consistencia de los datos en la tabla temporal tras dispararse el evento.

  • D. Modifica el evento del apartado A para que, a partir de hoy, actúe de forma recurrente cada mes durante el plazo de un año.

  • E. Vuelve a comprobar los metadatos lógicos para visualizar la actualización del momento de ejecución.

  • F. Realiza una consulta que liste la totalidad de eventos creados bajo la base de datos liga.

  • G. Borra uno de los eventos de prueba del sistema validando el control de excepciones (IF EXISTS).

  • H. Apoyándote en una IA (especifica el prompt y el modelo utilizado), solicita el código para un evento deMySQL que durante 1 hora, registre cada 5 minutos los usuarios concurrentes conectados al servidor MySQL en una tabla de auditoría dedicada. Explica mediante comentarios de bloque en el código la funcionalidad de cada línea y demuestra su funcionamiento con al menos 2 sesiones activas simultáneamente en tu taller.
