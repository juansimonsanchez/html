1. DESCRIPCIÓN GENERAL DE LA TAREA. OBJETIVOS ¶

Como administradores de sistemas (SysAdmins) o administradores de bases de datos (DBAs), es crítico dominar las bases lógicas y físicas de cómo almacena la información nuestro SGBD. Antes de poder automatizar planes de respaldo complejos en un entorno empresarial, debemos entender la diferencia entre los motores clásicos de MySQL, aprender a manipular los archivos en frío del sistema de ficheros de Linux y controlar las herramientas estándares de línea de comandos de exportación lógica como mysqldump y directivas del motor (SELECT INTO OUTFILE / LOAD DATA).

En esta tarea individual, realizarás una batería de 5 ejercicios prácticos diseñados para asimilar estos conceptos fundamentales.

2. CONSIDERACIONES PREVIAS ¶

  • Entorno de Trabajo: Máquina virtual (instancia en nube OpenStack o local) con Ubuntu 24.04 LTS.

  • Software: MySQL Server 8.0+ instalado y activo.

  • Permisos del sistema: Es necesario poseer
privilegios de sudo en el sistema operativo Linux anfitrión y acceso
como root al servidor de base de datos MySQL.

  • Variable secure_file_priv: Antes de comenzar, comprueba en qué directorio del sistema de archivos Linux tiene tu MySQL permitido realizar exportaciones directas de archivos (/var/lib/mysql-files/ por defecto).

3. ACTIVIDADES A REALIZAR (EJERCICIOS INDIVIDUALES) ¶

Ejercicio 1: Arquitectura física de almacenamiento y Motores (MyISAM / InnoDB) ¶

  • Crea la base de datos liga.

  • Añade una tabla de tipo MyISAM llamada tabla_myisam con campos básicos. Recuerda declarar de forma explícita ENGINE=MyISAM.

  • Añade otra tabla estándar de tipo InnoDB llamada tabla_innodb (por defecto).

  • Accede al shell del sistema operativo Linux host y localiza la ruta física donde MySQL guarda los datos en disco (/var/lib/mysql/). Documenta la diferencia estructural entre el directorio de la base de datos liga y detalla qué archivos físicos corresponden a las dos tablas creadas.

Ejercicio 2: Copias de Seguridad Físicas en Frío ¶

  • Diseña un protocolo secuencial en la consola de comandos de Linux para realizar un respaldo completo físico y en frío de la base de datos liga.

  • Simula una catástrofe de pérdida de datos en la que borres los archivos físicos de la base de datos (con el SGBD apagado) y procede a su restauración binaria en disco. Comprueba y justifica que el servicio arranca de forma íntegra.

Ejercicio 3: Exportación/Importación de Datos Planos (SELECT INTO OUTFILE / LOAD DATA) ¶

  • Exporta los datos de una tabla utilizando la instrucción SELECT INTO
OUTFILE en formato de texto plano delimitado por comas (.csv o .txt)
dentro del directorio permitido por el sistema.

  • Abre el archivo generado en una aplicación de hoja de cálculo (Excel o LibreOffice Calc) e incluye una captura mostrando el formato correcto de las columnas.

  • Crea una tabla vacía con la misma estructura y procede a poblarla con el archivo plano generado utilizando exclusivamente la sentencia SQL LOAD DATA.

Ejercicio 4: Uso avanzado de la Consola con mysqldump ¶

  • Realiza las siguientes copias de seguridad a través de la consola del sistema operativo utilizando la herramienta mysqldump de MySQL (justifica los comandos utilizados):

    1. Exporta la tabla partidos de la base de datos liga (estructura y datos).

    2. Exporta la estructura y datos de la tabla partidos eliminando los comentarios del archivo para reducir su peso (parámetro --compact).

    3. Exporta únicamente la estructura (DDL) de la tabla partidos omitiendo sus datos.

    4. Exporta únicamente los datos (DML en formato INSERT) omitiendo la creación de tablas.

    5. Exporta toda la base de datos liga en un archivo estructurado en formato XML.

    6. Exporta todas las tablas de liga a archivos separados en formato CSV.

    7. Exporta la base de datos liga completa con sentencias de base de datos incluidas.

    8. Exporta la totalidad de bases de datos del servidor MySQL (--all-databases).

Ejercicio 5: Restauración lógica mediante consola y comandos internos ¶

  • Ejecuta y documenta la restauración del respaldo completo generado de la base de datos utilizando dos vías:

    • Opción A: A través de la redirección de entrada de comandos del sistema operativo (<).

    • Opción B: Autenticado en el cliente de MySQL con la orden interactiva SOURCE o su equivalente \..

5. SOLUCIONARIO TÉCNICO DETALLADO ¶

Ejercicio 1: Arquitectura física de almacenamiento y Motores (MyISAM / InnoDB) ¶

CREATE DATABASE IF NOT EXISTS liga;
USE liga;

-- Creación explícita MyISAM
CREATE TABLE tabla_myisam (
id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
nombre VARCHAR(100) NOT NULL,
fecha_registro TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=MyISAM;

-- Creación InnoDB
CREATE TABLE tabla_innodb (
id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
nombre VARCHAR(100) NOT NULL,
fecha_registro TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

Explicación física (SysAdmin Linux Host): ¶

Ejecutando en el host: sudo ls -lh /var/lib/mysql/liga/

  • MyISAM (tabla_myisam): Veremos los archivos:

    • tabla_myisam.MYD (Almacena de forma plana los datos de los registros).

    • tabla_myisam.MYI (Almacena los índices estructurados).

  • InnoDB (tabla_innodb): Veremos únicamente el archivo:

    • tabla_innodb.ibd (Almacena conjuntamente en el mismo archivo los datos de filas e índices, aislado gracias a innodb_file_per_table=ON).

Ejercicio 2: Copias de Seguridad Físicas en Frío ¶

# 1. Detener el servicio del motor de base de datos MySQL de forma controlada
sudo systemctl stop mysql

# 2. Verificar que el proceso ha finalizado correctamente
sudo systemctl status mysql

# 3. Realizar un archivo tar comprimido del directorio físico de la base de datos liga
sudo mkdir -p /backup_ruta_segura
sudo tar -cpvzf /backup_ruta_segura/backup_fisico_liga.tar.gz /var/lib/mysql/liga/

# 4. Simulación de catástrofe de pérdida de datos (borrar directorio físico)
sudo rm -rf /var/lib/mysql/liga/

# 5. Proceso de Restauración binaria en frío
# Descomprimir el volumen en la ruta original de datos de MySQL
sudo tar -xpvzf /backup_ruta_segura/backup_fisico_liga.tar.gz -C /

# 6. MUY IMPORTANTE: Asignar de nuevo el propietario y grupo 'mysql' a los archivos restaurados
sudo chown -R mysql:mysql /var/lib/mysql/liga/
sudo chmod -R 700 /var/lib/mysql/liga/

# 7. Iniciar el servicio del servidor de base de datos
sudo systemctl start mysql

Ejercicio 3: Exportación/Importación de Datos Planos (SELECT INTO OUTFILE / LOAD DATA) ¶

-- 1. Consultar ruta segura permitida en el SGBD
SHOW VARIABLES LIKE 'secure_file_priv';
-- Supongamos que la ruta devuelta es: '/var/lib/mysql-files/'

-- 2. Exportación directa delimitada
SELECT id, nombre, fecha_registro
INTO OUTFILE '/var/lib/mysql-files/partidos_export.csv'
FIELDS TERMINATED BY ','
OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n'
FROM liga.tabla_innodb;

-- 3. Importación lógica en tabla clonada
DROP TABLE IF EXISTS liga.tabla_innodb_backup;
CREATE TABLE liga.tabla_innodb_backup LIKE liga.tabla_innodb;

LOAD DATA INFILE '/var/lib/mysql-files/partidos_export.csv'
INTO TABLE liga.tabla_innodb_backup
FIELDS TERMINATED BY ','
OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n'
(id, nombre, fecha_registro);

Ejercicio 4: Uso avanzado de la Consola con mysqldump ¶

# Supongamos que el usuario es 'root' y la tabla a exportar es 'tabla_innodb' de la base de datos 'liga'

# 1. Exportar la tabla (estructura DDL y datos DML)
mysqldump -u root -p liga tabla_innodb > 01_backup_tabla_completa.sql

# 2. Exportar la estructura y datos compactando el archivo (sin comentarios explicativos)
mysqldump -u root -p --compact liga tabla_innodb > 02_backup_tabla_compacta.sql

# 3. Exportar ÚNICAMENTE la estructura de la tabla (sin insertar datos de registros)
mysqldump -u root -p --no-data liga tabla_innodb > 03_backup_tabla_solo_estructura.sql

# 4. Exportar ÚNICAMENTE los datos (sentencias INSERT, omitiendo DDL de la tabla)
mysqldump -u root -p --no-create-info liga tabla_innodb > 04_backup_tabla_solo_datos.sql

# 5. Exportar la base de datos liga en formato estructurado XML
mysqldump -u root -p --xml liga > 05_backup_liga_xml.xml

# 6. Exportar las tablas de la BD liga a archivos CSV separados por comas
mysqldump -u root -p --tab=/var/lib/mysql-files/ --fields-terminated-by=',' --fields-enclosed-by='"' --lines-terminated-by='\n' liga

# 7. Exportar la base de datos liga completa (incluyendo definición del esquema)
mysqldump -u root -p --databases liga > 07_backup_liga_esquema_completo.sql

# 8. Exportar la totalidad de bases de datos del servidor MySQL
mysqldump -u root -p --all-databases > 08_backup_completo_servidor.sql

Ejercicio 5: Restauración lógica mediante consola y comandos internos ¶

Opción A (Consola del Sistema Operativo - Redirección externa): ¶

# Si el backup incluye la directiva CREATE DATABASE (generado con --databases)
mysql -u root -p < 07_backup_liga_esquema_completo.sql

# Si el backup no incluye la base de datos y solo tiene tablas, se debe especificar el destino
mysql -u root -p liga < 01_backup_tabla_completa.sql

Opción B (Cliente interactivo de MySQL): ¶

mysql -u root -p

mysql> USE liga;
mysql> SOURCE /var/lib/mysql-files/01_backup_tabla_completa.sql;
