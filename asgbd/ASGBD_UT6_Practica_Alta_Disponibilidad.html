1. DESCRIPCIÓN GENERAL. OBJETIVOS ¶

Objetivo: Configurar y gestionar un clúster de alta disponibilidad basado en MySQL Group Replication en modo Single-Primary.

2. ACTIVIDADES A REALIZAR ¶

Fase 1: Preparación (Entorno) ¶

  • Utiliza el entorno de 3 nodos (mysql1, mysql2, mysql3) definido en el docker-compose.yml.

  • Asegúrate de que los volúmenes están limpios antes de empezar: docker-compose down -v.

Fase 2: Desarrollo Paso a Paso ¶

Ejercicio 1: Puesta en marcha y Bootstrap del Clúster (2 puntos)

  1. Levanta los servicios: docker-compose up -d.

  2. Accede al nodo 1 (el que iniciará el grupo): docker exec -it mysql1 mysql -uroot -prootpassword

  3. Ejecuta los comandos de inicialización:
    -- Configura el canal de recuperación
    CHANGE MASTER TO MASTER_USER='repl', MASTER_PASSWORD='replpassword' FOR CHANNEL 'group_replication_recovery';
    -- Activa el bootstrap para crear el grupo
    SET GLOBAL group_replication_bootstrap_group=ON;
    START GROUP_REPLICATION;
    SET GLOBAL group_replication_bootstrap_group=OFF;

  4. Entrega: Captura del comando SELECT * FROM
performance_schema.replication_group_members; mostrando el nodo 1 como
ONLINE.

Ejercicio 2: Unión de Nodos Secundarios (2 puntos)

  1. Accede a mysql2 y mysql3 de forma secuencial.

  2. En cada uno, ejecuta:
    CHANGE MASTER TO MASTER_USER='repl', MASTER_PASSWORD='replpassword' FOR CHANNEL 'group_replication_recovery';
    START GROUP_REPLICATION;

  3. Entrega: Captura desde el nodo 3 donde se visualicen los 3 miembros en estado ONLINE. Identifica cuál es el MEMBER_ROLE de cada uno.

Ejercicio 3: Verificación de Replicación Síncrona (2 puntos)

  1. En el Primario (normalmente mysql1), crea
datos:
CREATE DATABASE alta_disponibilidad;
USE alta_disponibilidad;
CREATE TABLE nodos (id INT PRIMARY KEY, nombre VARCHAR(50));
INSERT INTO nodos VALUES (1, 'Nodo Primario Inicial');
  2. Accede a mysql3 (Secundario) y verifica la recepción
inmediata:
SELECT * FROM alta_disponibilidad.nodos;

  3. Entrega: Captura de la consulta en el nodo 3 y explicación de por qué no ha sido necesario crear la base de datos manualmente en este nodo.

Ejercicio 4: Simulación de Fallo y Failover (2.5 puntos)

  1. Identifica el UUID del primario actual.

  2. Desde el terminal del host, "mata" el contenedor primario: docker stop mysql1.

  3. Ve a mysql2 y consulta de nuevo la tabla de miembros.

  4. Entrega: Captura donde se vea que mysql1 ha desaparecido o está UNREACHABLE y que un nuevo nodo ha pasado de SECONDARY a PRIMARY.

Ejercicio 5: Reincorporación de un Nodo (1.5 puntos)

  1. Inicia el contenedor: docker start mysql1.

  2. Entra al MySQL de ese nodo e intenta unirlo al grupo: START GROUP_REPLICATION;.

  3. Entrega: Captura final con los 3 nodos de nuevo en ONLINE. Explica qué es el estado RECOVERING que aparece brevemente.
